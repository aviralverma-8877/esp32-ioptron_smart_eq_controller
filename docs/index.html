How to flash

  1. Plug the board into your computer with a USB-C data cable.
  2. Click Connect & Flash and pick the USB-SERIAL CH340 port.
  3. The CH340 auto-reset circuit drops the ESP32 into its bootloader on its own — no button holding needed. Wait for it to finish and reboot.
  4. On first install, choose Erase device if offered (clears any old Bluetooth pairing / NVS).

After flashing: pair SmartEQ-RJ9 from your phone / PC (see Bluetooth & Stellarium) and open the serial port it creates at 9600 8-N-1. Updating from an older version? Remove “SmartEQ-RJ9” from your phone / PC's Bluetooth devices first, then pair again.

Bluetooth & Stellarium

The controller works like a plain serial Bluetooth module: always visible, pairs without a code, nothing to press on the controller. Anyone in Bluetooth range can connect; one device at a time. Pairings are remembered across reboots and updates.

Pair a phone or PC

  1. On the phone / PC: add Bluetooth device SmartEQ-RJ9 and tap Pair.
  2. In Stellarium Mobile: tap Select in the telescope panel, wait for the scan and pick SmartEQ-RJ9.

“Connection to service failed” on Android? The phone remembers an old pairing the controller no longer has, and Android hides its Pair prompt in a notification. Tap Select to scan again, pick SmartEQ-RJ9 and tap Pair.

The same screen lists paired devices — select one twice to forget it. Windows creates two COM ports per pairing: use the Outgoing one (Settings → Bluetooth & devices → More Bluetooth settings → COM Ports). The Incoming port hangs any program that opens it.

Protocol — LX200 / NexStar translation

The mount speaks the iOptron command language, which most apps have no built-in driver for. The controller can translate: Menu → Bluetooth → Protocol (BOOT cycles it; the setting is saved).

ProtocolUse with
iOptron (default)byte-transparent — iOptron Commander, ASCOM iOptron driver
LX200Stellarium Meade LX200 (compatible), SkySafari Meade LX-200 Classic, INDI LX200 Basic, ASCOM Meade Generic
NexStarStellarium Celestron NexStar (compatible), SkySafari Celestron NexStar / Advanced GT, INDI Celestron NexStar

Translated: position, GoTo, sync, stop, slewing status, manual moves and rates, tracking on/off, park (→ zero position), time and site. Time and site sent by the app are written to the mount while the GPS has no fix (indoors, cold start); with a fix the GPS stays in charge. Half-hour zones such as India's +5:30 are kept correct even though NexStar apps send whole hours. While an LX200 / NexStar app is connected the GPS sync still runs. After every GoTo the controller makes sure the mount is tracking. The status header shows the active protocol (e.g. MOUNT OK LX200).

Stellarium — direct (recommended)

  1. On the controller set Protocol: LX200.
  2. Stellarium → Telescope Control (Ctrl+0) → add → Stellarium, directly through a serial port.
  3. Serial port: the Outgoing Bluetooth COM port · device model Meade LX200 (compatible) · coordinate system JNow.
  4. Select an object and press Ctrl+1 to slew (Ctrl+3 sync, Ctrl+5 abort).

Protocol NexStar with Celestron NexStar (compatible) works the same way (no sync in Stellarium's NexStar driver). Stellarium Mobile on Android: tested with Protocol NexStar — pick a Celestron NexStar telescope over Bluetooth → SmartEQ-RJ9 (GoTo, direction buttons and stop work; turn on the Time / Location Sync switches to set the mount from the phone — it then shows Time: correct). SkySafari on Android: Settings → Telescope → Setup, scope type as in the table, mount Equatorial GoTo (German), connect via Bluetooth. iPhones can't use Classic Bluetooth serial ports.

Stellarium via ASCOM (Protocol: iOptron)

  1. Install the ASCOM Platform and iOptron Commander 2014 (driver “iOptron CEM60, iEQ45Pro/30Pro, CEM25, SmartEQ Pro+…”).
  2. Start Commander once, pick the Outgoing Bluetooth COM port, connect, close.
  3. Stellarium → Telescope Control (Ctrl+0) → add: ASCOM, that iOptron driver, equinox JNow, connect at startup.
  4. Select an object and press Ctrl+1 to slew (Ctrl+3 sync, Ctrl+5 abort).

If the controller restarts while connected, close Stellarium (and iOptron Commander) and start Stellarium again — Windows doesn't reopen the Bluetooth link on its own. In this mode, after Go to zero position the mount stops tracking and a Stellarium GoTo won't restart it: abort, then turn tracking on in Commander (the LX200 / NexStar modes handle this automatically).

SD card — sky catalog & GoTo

Put this on a micro-SD card, insert it in the display module's slot and the controller gains an object browser: pick a target, read what it is and how to image it, then TRACK — the mount slews there and keeps tracking.

Messier objects, bright stars, planets & the Moon.

Download SD image (.img) flash with balenaEtcher / Rufus · any card ≥ 64 MB Download files (.zip) unzip onto a FAT32 card · keeps full capacity

Option A — flash the image

  1. Download smarteq-sd.img.zip (no need to unzip).
  2. Open balenaEtcher (or Rufus), choose the zip, select your SD card, and flash. Everything on the card is erased.
  3. The card shows up as a 64 MB drive named SMARTEQ; the rest of a larger card stays unused.

Option B — copy the files

  1. Format the card as FAT32.
  2. Unzip smarteq-sd-files.zip to the card's root so it contains a SMARTEQ folder.

Using it

ButtonAction
Aup (hold = fast scroll) · previous object
Bdown (hold = fast scroll) · next object
BOOTselect / open / TRACK (press again to confirm)
BOOT heldback · cancel an armed TRACK
any button while slewingstop the mount

TRACK is only enabled for objects at least 10° above the horizon and 15° away from the Sun. GoTo is disabled while a Bluetooth app is connected. The menu also has Sync GPS now, Stop mount, Go to zero position (select twice to confirm), Time zone (Auto from GPS, or A/B in 15-minute steps), Bluetooth (pair / forget devices, client protocol) and Factory reset (select twice: forgets paired devices and settings, then reboots). Don't hold BOOT while powering on or resetting.

What gets written

OffsetRegion
0x10002nd-stage bootloader
0x8000partition table (huge_app, 3 MB app / no OTA)
0xe000boot_app0
0x10000application

All four are combined into smarteq-rj9-merged.bin (flash to 0x0), rebuilt on every pio run.
